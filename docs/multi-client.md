# ใช้งานหลาย client

## วิธีเริ่มระบบ

ทุกเครื่องใช้งานเว็บจากเซิร์ฟเวอร์เดียวและ PostgreSQL เดียว ไม่ต้องติดตั้งฐานข้อมูลแยกต่อ client ใช้บัญชีแยกคนเพื่อบันทึกผู้แก้ไขได้ถูกต้อง

```powershell
docker compose up -d --build web
docker compose exec web python manage.py check
docker compose exec web python manage.py test
```

ตั้งค่าเริ่มต้นเป็น Gunicorn 2 workers × 4 threads รองรับงาน HTTP พร้อมกันได้ 8 threads สำหรับเริ่มใช้งานทีมประมาณ 6 คน จำนวนนี้ไม่ใช่ผล benchmark ความเร็วจริงขึ้นกับเครื่อง server และฐานข้อมูล

เปิดพอร์ต 8085 ผ่านทุก interface โดย `WEB_BIND_ADDRESS=0.0.0.0` ตั้ง `DJANGO_ALLOWED_HOSTS` ใน `.env` ให้มี IP หรือชื่อ host ของ server โดยไม่ใส่ port ไม่ใช้ wildcard ฐานข้อมูลไม่มีพอร์ตเปิดสู่ client

IP Wi-Fi ที่ตรวจพบวันที่ 10 พ.ย. 2026 คือ `10.84.184.84` เพิ่มใน `.env` แล้ว เครื่องอื่นในเครือข่ายเปิด `http://10.84.184.84:8085` ได้เมื่อ routing/firewall อนุญาต หาก IP เปลี่ยนต้องแก้ allowed hosts และสร้าง container ใหม่ แนะนำจอง IP ของ server ให้คงที่ หากยังเข้าไม่ได้ให้ฝ่าย IT อนุญาต TCP 8085 จากเครือข่ายทีมเคลมตามนโยบายบริษัท ไม่จำเป็นต้องเปิดพอร์ต PostgreSQL

## การป้องกันข้อมูลชนกัน

- เมื่อเปิดฟอร์ม/รายการ ระบบส่ง version จาก `updated_at` มากับหน้า
- เมื่อบันทึก ระบบ lock แถวเอกสารด้วย PostgreSQL `SELECT FOR UPDATE` ภายใน transaction แล้วตรวจ version ก่อนแก้ข้อมูล
- เอกสารคนละฉบับบันทึกแยกกันได้ เอกสารเดียวกันและ version เดียวกันบันทึกสำเร็จได้เพียงคนแรก
- หากข้อมูลเปลี่ยนไปแล้ว ระบบตอบ 409 และแสดงข้อความแจ้ง ข้อมูลที่พิมพ์ยังอยู่ในฟอร์มเดิม พร้อมลิงก์เปิดฉบับล่าสุดในแท็บใหม่สำหรับเปรียบเทียบ ไม่ merge หรือทับให้อัตโนมัติ
- หัวเอกสารและสินค้าบันทึกใน transaction เดียว ล้มเหลวแล้ว rollback ทั้งชุด
- Dropdown เปลี่ยนสถานะใช้ lock และ version แบบเดียวกัน จึงตรวจพบแม้สถานะเปลี่ยนไปแล้วเปลี่ยนกลับ
- เลขที่เอกสารมี unique constraint ป้องกันสร้างเลขซ้ำพร้อมกัน เมื่อชนกันจะโหลดเอกสารเดิมหรือแสดงข้อผิดพลาด ไม่แทนสินค้าของเอกสารเดิม
- Django Admin สำหรับ Claim เป็น read-only เพื่อให้การแก้เอกสารผ่านฟอร์มที่ตรวจ version เสมอ จัดการบัญชีผ่านเมนูจัดการบัญชีได้ตามเดิม

การเขียนฐานข้อมูลโดยตรงจาก SQL หรือสคริปต์ภายนอกต้องปฏิบัติตาม lock/version protocol นี้ด้วย ระบบนี้ไม่ได้ห้ามผู้ใช้สองคนเปิดเอกสารเดียวกัน แต่ป้องกันบันทึกทับจากฉบับเก่า

## การตรวจสอบ

`claims/test_concurrency.py` ใช้ PostgreSQL จริงและ 6 threads/client พร้อมกัน ทดสอบเอกสารเดียวกัน, เอกสารคนละฉบับ, เลขเอกสารใหม่ซ้ำ, สถานะชนกับฟอร์ม และ request ที่ไม่มี version

```powershell
docker compose exec web python manage.py test claims.test_concurrency
```

session ที่แก้โค้ดยังเรียก Docker/Python ที่ติดตั้งในเครื่องไม่ได้ จึงยังไม่ได้รัน Django tests หรือ load test จริง และยังไม่ได้ยืนยันการเข้าเว็บจากเครื่อง client ในเครือข่าย
